# ADR：原生客户端共用产品契约

- 状态：已采纳
- 日期：2026-09-12

## 背景

macOS 已实现完整的个人词库和词库资源管理，Windows 首版只复用了外观方向，保留了简化功能。相同产品在不同系统出现不同页面、操作顺序和数据语义，用户跨设备时需要重新学习，也让后续功能容易继续漂移。

## 决定

以产品领域契约和平台适配器分层：

1. 产品层固定页面、操作、状态、确认、撤销、失败恢复和数据保留规则。
2. 资源清单、第三方来源元数据、个人词库 TSV、模型描述和校验值使用共用格式及构建来源。
3. macOS 与 Windows 分别使用 Swift/AppKit/IMK 和 C#/WPF/TSF 实现界面与系统接入。
4. 词库资源都通过“准备新代次、隔离编译、真实候选验证、等待组合结束、切换、失败回退”状态机。
5. CI 运行平台无关的一致性契约检查，并由各平台运行真实引擎和安装测试。

## 取舍

直接共用一套 UI 运行时可以减少界面代码，但会削弱输入法所需的原生窗口、辅助功能、安装和系统菜单接入，并增加分发依赖。继续保留两套互不约束的客户端最省当前改动，却无法阻止功能再次漂移。因此保留原生 UI，实现层不要求逐函数同名；领域对象、文件格式、状态转换和验收标准保持一致。

## 失败与安全

- 个人库编辑前比较最新快照，避免覆盖输入进程刚产生的学习。
- 第三方词库限制文件类型、UTF-8、大小、列结构、全拼音节、词条数和权重；编译器使用独立临时用户目录。
- 资源代次通过受限 UUID 路径和标记文件解析，不接受任意活动路径。
- 切换失败恢复上一个活动代次或内置资源，个人学习库不参与资源复制和清理。
- 外部进程使用筛选后的普通 Windows 环境，不传递开发环境凭据。

## 结果

新增功能需要同时更新客户端一致性文档、两端入口和相应运行测试。平台特有能力可以单独存在，但必须明确属于系统适配，而不是另一套产品逻辑。
