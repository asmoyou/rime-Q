# 同步性能与 Windows 页面修正

用户已要求同时修复性能、Windows 页面布局和连接提示抖动，并覆盖 macOS 的同类问题；按现有授权直接实施。

采用保留原生 WPF/AppKit 的方案。Windows 对齐 Mac 的信息层次：标题与说明、同步组摘要、稳定的结果/进度区域、可搜索设备列表、主要操作及更多菜单。短暂后台握手不显示成新增行；错误和真正待处理状态保留。保留系统字体、明暗/高对比度和键盘可访问性，不引入网页壳或装饰动画。

性能优先修正重复工作：共享核心缓存条数/版本，无变化 capture 不重写基线，无变化回执复用；空闲网络检查延长，有变更时及时唤醒同步，手动立即执行。两端协调器降频并去重探活，合并短时间学习变化。Mac 改为直接连接本地控制服务，消除每次查询新建进程。继续保留保守的学习变化覆盖，先以节流避免遗漏删除/导入等学习事件；不以简单“只看上屏”换取降低占用。

替代方案：仅延长定时器虽然改动小，但仍有整库扫描和写入，不能解决成本随词库增长；重写整个同步协议成本过高且增加迁移风险。本次保持协议及数据目录，优先减少已证实的重复操作。

步骤：共享核心与回归；双端协调器/通信与节流；Windows 页面和双端稳定进度；真实原生截图及隔离引擎/TLS测试；对照资源测量；更新验证记录，统一版本并完成相关 CI 和既有授权发布流程。不得为测试停用当前输入法或改写真实词库。

验证包含无变化不写盘、真实变更/删除/撤销权限传播、应用回执、离线/重连、手动强制与失败退避、长组合保护、重复状态不扫描全表、Windows 页面多次传输状态切换几何位置不变、深浅/紧凑/错误/邀请场景。Mac 原生编译及验证由同一提交的 CI 完成，本机结果不替代 Mac 验收。
