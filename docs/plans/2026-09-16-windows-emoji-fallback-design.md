# Windows 候选栏 emoji 字体回退设计

## 目标

Windows 候选栏必须显示基础符号、补充平面 emoji、变体选择符、肤色、ZWJ、键帽和中英混排，不把不同字符统一画成缺字方框。中文继续以 Microsoft YaHei UI 为首选，候选测量、截断和绘制使用同一套布局；浅色、深色、四档字号及高 DPI 下不改变鼠标选词索引或候选窗口几何。

## 方案

保留现有 GDI+ 圆角、皮肤和敲敲猫矢量绘制，将候选文字切换到 DirectWrite 排版，并使用系统字体回退。包含 emoji 的连续序列优先交给 Segoe UI Emoji，范围包含代理对、变体选择符、肤色修饰符、ZWJ 链、键帽和区域指示符。Direct2D 在透明 WIC 位图上一次绘制整张候选文字层，开启系统彩色字体，再由 GDI+ 合成到原有 32 位分层窗口；高对比度模式禁用彩色层并使用系统前景色。

没有采用全局 Segoe UI Emoji，因为会改变中文字体与宽度；没有采用逐码点 GDI+ 切字体，因为它会拆散 ZWJ、肤色和键帽序列。整层批量绘制也避免为每个编号、正文和注释分别创建渲染目标。

## 验证

自动回归比较多个补充平面 emoji 的实际像素，若它们再次折叠成同一个缺字方框则失败。原生截图覆盖 `❤`、`☀`、`😀`、`🎉`、`🚀`、`❤️`、`👍🏽`、`👨‍👩‍👧‍👦`、`1️⃣`、`🇨🇳`、`⌚`、`↔️`、`⭐` 和中文混排，并生成 16/18/20/22 字号、明暗皮肤及 200% 缩放结果。x64 与 x86 均执行相同候选测试；真实已安装 TIP 的宿主输入仍需使用递增构建安装后单独验收。
