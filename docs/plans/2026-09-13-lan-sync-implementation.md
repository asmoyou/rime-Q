**目标：** 在个人词库中加入默认关闭的多设备同步组，先在隔离环境验证至少六个网络节点，然后验证原生引擎和客户端。

**架构：** 网络辅助进程与输入进程分离。共用带签名的记录协议、因果合并和持久日志，原生客户端通过受本机身份约束的接口在空闲时读写学习库。每台设备独立学习与转发，加入同步组一次，无固定主电脑。

**技术选择：** 共用服务采用 Rust，使用成熟密码/TLS/发现库及 SQLite；原生界面继续 Swift/AppKit 和 C#/WPF。相对提案的 C++ 建议，这一选择减少网络解析与内存安全负担，并提供相同的跨平台服务代码；代价是构建中增加 Rust 工具链及依赖许可、安全维护。具体依赖由 Cargo.lock 锁定，随包保留许可。

## 1. 共用状态与合并

- 新建 `sync/Cargo.toml`、`sync/src/model.rs`、`sync/src/store.rs`、`sync/src/identity.rs`。
- 先写并发学习、删除优先、删除后重新学习、降低权重、重复和乱序、缺口、六节点分区与接力的集成测试。
- 使用设备独立签名、持久序号及因果版本。SQLite 事务记录收到的数据、合并状态、应用基线；不以最后收到的文件覆盖词库。
- 在真实引擎之外先运行 `cargo test --manifest-path sync/Cargo.toml --locked`；失败时修复后再继续。

## 2. 网络、配对及本机控制

- 新建 `sync/src/network.rs`、`sync/src/service.rs`、`sync/src/main.rs`；实际发现逻辑位于 `service.rs`，没有独立 `discovery.rs`。
- 默认不监听；用户开启后启用本地网络发现和加密传输。配对限时、限次并绑定设备密钥，成员管理与数据操作授权分别校验。
- 本机控制只监听回环且要求私有随机凭据；远端连接不能访问控制接口。帧大小、词条、序号、上下文及错误输出均有界。
- 真实网络进程测试包括拒绝未授权设备、错误配对、重放、移除、重启恢复及不误报应用完成。
