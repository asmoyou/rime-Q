# 客户端功能一致性

Rime Q 在 macOS、Windows 和后续 Linux 客户端中使用同一套产品能力。原生控件可以遵循系统习惯，但页面层级、操作名称、数据规则、确认与撤销、状态反馈及失败后的保留行为必须一致。

## 设置页契约

| 页面 | 两端共同能力 |
| --- | --- |
| 输入与外观 | 整句优化状态与说明；模型下载、取消、校验、重试和确认移除；相邻键容错与正确拼音提示，组合结束后生效；候选字号与皮肤；真实候选预览；常用按键与快捷输入，Caps Lock 保持原中英文模式 |
| 个人词库 | 打开即读取；按词条或全拼搜索；按学习权重、词条、拼音排序；多选；新增、编辑、确认删除；修改前自动备份；撤销上次修改；确认导入并按同词同拼音合并较高权重；导出全部；空结果与总数状态 |
| 附近设备同步（开发中） | 从个人词库进入，未启用时只查看不启动服务或创建身份；分别创建、加入、邀请；发现、六位配对码、等待取消、过期反馈与原设备确认；连接信息采用相同三行格式并可粘贴，多局域网地址可选，服务失败可重试；逐成员应用回执；暂停、继续、创建者移除；退出归档与恢复快照。实际范围与待验收边界见 LAN_SYNC.md |
| 词库与模型 | 列出内置词库、第三方词库及可选模型；来源、版本、许可、摘要与状态；导入独立全拼词库；启停可选资源；移除第三方词库但保留原文件；查看词条；导出源文件；重新应用；确认恢复内置配置 |
| 版本与更新 | 版本和构建号；每天一次后台检查开关；手动检查；新版本、当前版本、无公开版本及失败状态；发布记录、项目、许可与卸载 |
| 皮肤 | 相同皮肤集合、名称、说明、选中状态与候选预览；高级动态皮肤独立展示；减少动态效果时停止动作 |

系统输入法菜单或托盘菜单均提供设置、个人数据文件夹、使用说明、检查更新和卸载。卸载默认保留个人词库、设置、导入词库源文件及模型。

## 共用规则

- 两端的个人词库使用 rime_q 用户词典及同一 TSV 交换格式。学习权重是排序参考，不描述为实际输入次数。
- 个人词库修改只影响指定词条。写入前重新读取并检查同一词条是否被新的学习修改；冲突时停止覆盖。
- 新增、编辑、删除和导入前保存完整个人词库备份。删除使用 librime 的删除标记，内置同名词仍可出现。
- 词库清单由 scripts/dictionary_catalog.py 从同一份资源锁和实际文件生成，客户端不维护手写的第二份清单。
- 第三方词库保存原始文件、规范化 TSV、来源、版本、许可及 SHA-256。配置修改先在隔离用户目录编译并验证，再等待当前输入结束切换；失败继续使用原资源。
- 当前与上一代编译资源用于恢复。个人学习库和导入源文件不参与代次清理。
- 万象模型使用同一个依赖锁、资产内容、大小和 SHA-256。下载状态与应用版本分离。

## 平台边界

macOS 使用 InputMethodKit、AppKit、系统 Sheet 和应用 Bundle；Windows 使用 TSF、WPF、命名管道 Broker 和版本化安装目录。两端可以分别实现进程退出、系统注册、文件选择器、管理员认证、窗口材质和候选定位。这些适配不得改变产品操作的先后顺序、结果或数据保留规则。

Windows 远程控制可能不完整传递单独 Shift，因此在相同中英文状态机上增加 Ctrl+Space 和可点击的“中/A”任务栏按钮，并通过标准 TSF compartment 向系统发布当前模式。这属于平台输入兼容，不改变中文/英文模式语义。

python scripts/test_client_parity.py 检查两端已建立的页面和操作契约。平台构建继续负责真实引擎、原生窗口、安装、输入宿主和卸载验证；源码契约检查不能替代这些运行测试。
