内存、空闲 CPU、唤醒次数和真实应用端到端延迟尚未完成正式测量。当前基线不能证明已经优于其他输入法。

## 当前阻碍与残留排查

2026-09-10 后续排查确认：灰色 RIMES 来自 `com.apple.inputsources` 域的 `AppleEnabledThirdPartyInputSources`，仍保存 `com.isaac.inputmethod.RimeBuffer` 的父级和 Hans 模式两条记录。原应用已不在两个 Input Methods 安装目录或 LaunchServices 注册列表中。

macOS 的 cfprefsd 日志明确拒绝当前工具通道中的 Swift/`defaults` 进程写入该键，提示缺少 `user-preference-write` 或 `file-write-data` sandbox access。修改未落盘；不能把 TIS/defaults 返回成功当成已启用，也不能把此故障直接认定为必须注销。

已备份该域并生成只移除这两条旧 RIMES 记录的可审阅修复脚本。由于当前通道的实际系统限制，尚未清除原记录。需要用户亲自在本机终端执行后，再检查新读取的设置与菜单。

为核对空白条目，已将未启用的 Rime Q 应用移出 Input Methods 并取消该路径的 LaunchServices 注册，保留安装包、归档应用和独立个人数据。新进程的 TIS 列表只剩鼠须管，重新打开系统设置后空白条目仍存在，说明不能仅凭空白外观归因于当前 Rime Q 应用。仍需清理旧记录并刷新界面后复核。

当前没有在真实宿主应用完成 Rime Q 打字验收。Windows 和 Linux 客户端尚未实现；三平台核心测试与 Mac 通用包构建、引擎回归已通过 GitHub Actions（首个提交 `960a4b2`）。
