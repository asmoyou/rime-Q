# 开发计划

## 方向

面向普通简体中文用户，以输入延迟、候选质量和易用性作为取舍依据。独立维护 Rime Q，不以 RIMES 的完整功能集作为产品范围。

- 输入、排序和学习在本地完成，无广告、账号或遥测。
- 输入路径不联网；默认每 24 小时检查一次 GitHub 发布信息，可关闭，不上传输入内容，不自动下载或安装。无剪贴板轮询或本地 HTTP 服务。
- 只让输入接入所需模块常驻，设置与后续语音模块按需启动。
- 常用设置通过界面完成；输入方案、词库、模型由程序管理兼容性与部署。
- 个人数据独立保存，切换或停用输入方案不删除学习记录。

已确认：以 librime 为基础，吸收雾凇、万象及合适的网络词库，交付独立安装包。目标为 macOS、Windows、Linux，先在当前 Mac 完整验证。Rime Q 独立开发客户端并评估自己的排序与学习策略，不从零重写拼音切分或转换内核。

Windows 端已新增原生 TSF、进程外 librime、WPF 设置和独立 EXE 安装构建，入口见 [Windows 客户端](WINDOWS.md)。隔离集成与系统安装/外部宿主验收分别记录，不以构建或模拟按键结果替代真实宿主验收。

0.2.0 预览新增个人学习记录的图形管理，以及内置可选词库和第三方全拼词表的管理。功能与安装包已完成本机隔离验证，实际升级后的宿主输入验收见 `docs/VALIDATION.md`。完整输入方案包、双拼和其他平台仍按后续计划推进。

## 实施顺序

1. **算法基线**：可构建的独立核心库、精确编码下的候选学习、自造词召回、置顶和删除、持久化、回归测试与基准。
2. **基础输入闭环**：当前已接入 librime 并构建 Mac 预览包，继续在 macOS 验证预编辑、候选窗、翻页、选词、上屏、焦点切换；保持引擎候选身份和部分选词语义。
3. **日常可用**：简体全拼与双拼、个人词库管理、字体与候选数量等常用设置；真实应用测试、安装包和可恢复更新。
4. **可选资源**：0.3.1 已支持万象模型按需下载、校验、启停和移除；完整输入方案包安装和切换继续规划；兼容的专业词库按需叠加，模型依赖随方案处理。保留用户自己的皮肤与个人数据。
5. **后续能力**：本地语音识别、其他桌面平台。语音在基础输入达标后接入，按需加载、显式开始与停止录音。

## 验收依据

| 项目 | 验收内容 |
| --- | --- |
| 自造词 | 手工组词确认后，同编码再次输入时首屏可见，重启后仍能召回 |
| 常用单字 | 重复选择能提升该编码下的排名，不把同一个字的偏好错误套到其他读音 |
| 正确上屏 | 候选重新排序后，数字键、空格和鼠标仍选择所见条目；选前缀保留未转换部分 |
| 会话隔离 | 切换应用、输入框或输入源后不串词、不向旧输入框提交 |
| 数据完整性 | 更新、停用方案不清空学习库；保存失败可见，不以空库覆盖异常数据库 |
| 性能 | 分别记录冷启动、按键到候选 p50/p95/p99、提交延迟、空闲 CPU、内存和唤醒次数 |
| 离线 | 断网完成输入和学习；输入路径不联网；更新检查默认每 24 小时一次，可关闭，不上传输入内容 |

初始工程预算：64 个候选的个性化排序 p95 < 1 ms，后续完整输入路径 p95 < 16 ms。它们是开发预算，不是已经实现的整机性能承诺；基准必须记录机器、构建模式、样本规模和计时范围。

Ubuntu 上此前报告的“组合词不记忆、常用字长期靠后”仍需实际输入案例和配置复现。当前合成用例用于约束新实现的行为，不能据此宣称修复了另一台设备的问题。
