# 授权说明

Rime Q 的授权请求应对应清楚的操作，不要求用户笼统地“全部允许”。日常输入在本机处理，检查更新只在用户点击后联网查询 GitHub 发布信息。

| 看到的提示 | 申请方与用途 | 拒绝后的影响 |
| --- | --- | --- |
| 管理员认证 | 安装时由 macOS 安装器写入系统目录；用户选择卸载时，由 Rime Q 请求删除自身应用 | 本次安装或卸载不能继续 |
| 访问下载文件夹 | macOS 安装器读取用户下载的安装包 | 可能无法读取本次安装包；日常打字不依赖这个权限 |
| 控制 Rime Q | 更新助手请求仍在运行的旧版 Rime Q 正常退出，让新版接管 | 旧进程不能自动退出，可稍后完成升级 |
| 注销账户确认 | 用户明确选择注销后，向 macOS 发送正常注销请求 | 保持当前登录会话，稍后处理 |

安装器访问下载文件夹的提示属于 Apple 的安装器，Rime Q 不能修改它的系统文案；该请求也可能早于包内介绍页。因此 README、发布页面和安装器介绍页都应说明用途，不承诺包内说明总能在这个弹窗之前出现。

“控制 Rime Q”由更新时退出旧进程的 Apple events 兼容操作产生。请求方和被请求方可能都显示 Rime Q，因为新旧进程使用同一个产品名称。0.1.4 增加 `NSAppleEventsUsageDescription` 及中文本地化，明确只用于旧进程退出或用户主动选择的注销。同时，新版运行进程支持按应用路径和进程号匹配的正常退出通知；升级到支持该机制的版本后，后续更新优先使用这个方式，减少自动化授权。较早版本可能仍需要兼容请求，不承诺全部授权弹窗消失。

管理员密码或 Touch ID 只在 macOS 自己的认证窗口中输入，Rime Q 不收集这些信息。卸载保留个人词库与学习记录。

## 开发与排查

- 已从本机限定的 TCC 日志确认下载目录权限检查的主体是 `com.apple.installer`。检查记录不等同于弹窗出现次数。
- 开发工具操作系统设置、访达、文本编辑器或进行截屏时，可能另外请求自动化或屏幕访问；这些权限不能写成终端用户使用 Rime Q 的前置要求。
- 当前代码未添加下载目录用途声明来扩大输入法本身的访问范围。构建阶段的临时应用移到系统临时目录，减少开发测试从 Downloads 加载资源引起的额外访问。
- 系统支持用途字符串的请求，应写具体用途；不支持定制的系统提示，在已有介绍页、下载说明和帮助页解释。成功路径不增加额外的“权限说明确认”弹窗。
- 每次新增权限相关 API 都要核对触发时机、申请方、范围和取消后的行为。优先移除不必要的请求，不用文案合理化多余权限。
- 当前为 ad-hoc 签名开发预览。正式发布需另行验证稳定签名、公证和升级后的权限体验，不能把反复开发安装的提示次数当作正式产品指标。

Apple 提供的用途字符串机制见 [NSAppleEventsUsageDescription](https://developer.apple.com/documentation/bundleresources/information-property-list/nsappleeventsusagedescription)。
